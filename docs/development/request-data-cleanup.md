# 手动清理请求数据

本 fork 将账户额度的各个窗口改为独立请求，并在“系统信息”页提供手动请求数据清理。不会自动保留最近 15 天，也不会自动执行数据删除。

## 清理范围

- 管理员在“系统信息 → SQLite 存储”首行的 SHM 文件右侧选择截止时间；界面会自动预览待清理请求数，再经过两次确认提交清理。窄屏下控件自动换行。
- 清理范围为预览时已存在、请求时间严格早于截止时间的请求及对应请求统计；截止时间相同或更晚的请求不删除。
- 预览后新入库的请求不属于本次范围，即使它们携带较早的请求时间也会保留。
- 保留账号凭据、管理配置、模型价格、API Key 别名和配额生命周期等非请求数据。
- 死信记录无法仅凭入库时间可靠关联到请求截止时间，本功能不顺带删除。
- 如果截止时间进入当前配额周期，该周期的用量和额度预测可能因为依据被删除而不完整。请先确认所需历史已经备份。

## 执行与恢复

清理作业在后台分批执行。关闭页面仅停止浏览器的进度查询，不等同于取消后台清理；返回同一连接后可以继续查看进度。清理失败可能已经完成部分批次，应恢复同一作业，不要假定所有已删除数据已回滚。

清理后会从保留的请求重建对应统计。删除或重建未完成时，仪表盘、请求监控以及兼容用量/导出接口报告维护中，不应将部分结果当成完整统计或备份。已有归档或其他维护任务与清理不兼容时，后端会拒绝执行，不会跳过校验后强行删除。

## 后台执行与写锁协调

清理本身已在后台 goroutine 中运行，HTTP 提交后只查询进度。SQLite 同时只能有一个写事务，增加多个删除线程不能并行写入，反而会与请求采集和其他回填任务争锁。

- 清理作业接管账户历史、小时聚合及请求监控/价格等派生统计的回填；相应常驻 worker 暂时让出，避免同一份数据重复回填。请求采集、数据迁移和响应元数据准备不暂停。
- 删除每批最多 1,000 条；重建每次连续推进最多 8 轮小批事务，并在批次间短暂让步，不持有一个覆盖全部请求的大事务。
- `SQLITE_BUSY` / `SQLITE_LOCKED` 属于可重试的临时冲突，保持作业运行状态并退避；结构性错误仍报告失败，并区分删除阶段和重建阶段。
- 请求删除完成不等于整个作业完成。只有统计重建也完成才报告成功，无需额外重启 Manager Server、CPA 或其他服务。
- 若请求已经删除、重建失败，继续原作业即可从断点恢复统计。不要新建清理来尝试解除维护状态，更不能直接手工把作业状态改为完成。

SQLite 删除数据后首先释放的是数据库内部可复用空间，`usage.sqlite` 文件不一定立即缩小，WAL 还可能暂时增长。不要把“清理完成”等同于“磁盘文件已缩小”。需要压缩文件时，先备份，停止 Manager Server，再按官方离线维护流程处理；网页清理不会在线运行 `VACUUM`。

“SQLite 存储”的总占用是主库、WAL 与 SHM 的物理文件大小之和，不是有效请求数据量。内部空闲页会优先复用，不能仅凭总占用不变判断删除失败。可通过只读 `PRAGMA page_size`、`PRAGMA page_count` 和 `PRAGMA freelist_count` 核对；`page_size × freelist_count` 为整页级可复用空间，不包含仍在使用页面内的零散空闲空间。

2026-10-22 的一次线上只读核对：原作业已完成，目标与实际删除数均为 41,819；主库为 3,056,459,776 bytes，WAL 为 140,104,752 bytes，SHM 为 32,768 bytes，总计约 2.98 GiB。其中主库有 65,789 个 4,096-byte 空闲页，即约 257 MiB 可复用空间；后台采集继续写入时这些数值会变化。本轮没有执行新的删除或压缩。

## 与旧 15 天定时器的关系

旧自动清理由 VPS 上的外部 systemd 单元控制，不是 CPAMP 仓库内置规则。停止它不会删除已有请求，也不需要重启 CPA、newAPI 或 VPN：

```bash
sudo systemctl disable --now cpamp-retention.timer
systemctl show cpamp-retention.timer -p ActiveState -p UnitFileState
```

预期状态为 `ActiveState=inactive`、`UnitFileState=disabled`。定时器脚本可保留供人工恢复，不应在新部署脚本中重新启用。

## 开发和部署边界

本地代码改动不会自动更新 VPS。发布本 fork 时应构建和部署自己的镜像或二进制；继续使用官方 `seakee/cpa-manager-plus` 镜像不会获得本 fork 新增的功能。

额度窗口拆分保留原有凭证、连接和周期隔离校验，以及用量观测时间与额度百分比观测时间的一致性检查。历史窗口失败不再阻塞已经返回的当前窗口，但这不表示任何情况下都能够生成可信预测。
